# 第6回 大量データでの計測結果（2026-09-22）

## 計測方法

- データ: `tests/fixtures/largeData.ts` で生成（固定の乱数の種から作るので毎回同じ）。
- 本番の localStorage は使わない。計算は Node 上、画面は Playwright がテストごとに作る独立したブラウザ環境（Microsoft Edge、375px幅）で計測。
- 計測したPCは開発用のWindows PC。スマートフォンの実機では数倍かかる想定で読むこと。
- 再計測: `npm run perf`（計算のみ）／ `npm run perf:render`（画面。結果は `test-results/render-measure.txt`）

## 計算のみ（ミリ秒）

商品1,000・店舗100・価格履歴5,000（保存データ約814KB）

| 処理 | 変更前 | 変更後 |
|---|---:|---:|
| 保存データの読み込み・検証 | 15.8 | 14.4 |
| 価格比較の計算 | 46.3 | 2.1 |
| 買い物リストの組み立て | 44.7 | 2.3 |
| 価格履歴の検索 | 25.3 | 5.0 |
| 価格履歴の期間絞り込み | 3.2 | 0.1 |
| 全記録の並べ替え | 1.2 | 1.2 |
| 購入済みチェック1回の保存 | 21.2 | 26.4 |

価格比較・買い物リストは「商品ごとに全記録を調べる（商品数×記録数）」処理だったため、記録を商品別に1回だけ振り分ける形に変更した。

| 件数 | 画面 | 変更前 | 変更後 |
|---|---|---:|---:|

| | 価格履歴（全商品） | 294（11,209） | 99（763） |

| | 価格履歴（全商品） | 313（12,109） | 152（1,663） |

| | 価格比較 | 740（62,192） | 594（45,198） |

- 商品・店舗・価格履歴は、1ページ50件に分割したことで、件数が増えても描画量がほぼ一定になった。
- 価格比較は、PC用の表とスマホ用のカードを両方描画していたのを、画面幅に合う方だけにした（要素数を約3割削減）。ただし全商品を1画面に出すため、商品1,000件では依然として重い（今回の範囲外。課題として残す）。
- 買い物候補は方針どおりページ分割していない。目安以下の商品が数百件ある極端な場合に重くなる。
